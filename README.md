# Treker — трекер привычек для Android

Локальное Android-приложение на Kotlin и Jetpack Compose для ежедневных привычек, задач, таймеров и прогресса. Работает без аккаунта и сервера; хранит данные на устройстве в Room, настройки — в DataStore. Минимальная версия Android — 8.0 (API 26).

## Что реализовано

- Пять разделов: **Привычки**, **Сегодня**, **Шаблоны**, **Прогресс**, **Настройки**.
- Создание и редактирование привычек с категорией, описанием, цветом, расписанием (каждый день, выбранные дни недели или однократная дата) и напоминанием.
- Четыре способа отслеживания: простая отметка, счётчик с защитой от отрицательных значений, таймер с паузой/восстановлением по абсолютному времени, накопление времени сессиями по 15 минут.
- Единые дневные записи для карточек привычек и раздела «Сегодня», отметки «пропустить» и «не выполнено», просмотр прошлых дат.
- Встроенная библиотека шаблонов и пользовательские шаблоны, сохраняемые локально из меню привычки; тепловая карта на 12 месяцев, дневная статистика, серии и сравнение текущей/предыдущей недели.
- Темы «системная / светлая / тёмная», 6 акцентных цветов, первый день недели (понедельник/воскресенье), формат времени (24/12 часов), настраиваемое начало нового дня (00:00–06:00) и вид статистики (проценты или «выполнено из плана»).
- Звуки: «без звука», системный звук, три встроенных сигнала (короткий, двойной и длинный для таймера), пользовательский аудиофайл с устройства, предпрослушивание, отдельный звук для каждой привычки, вибрация и продолжительный сигнал завершения таймера. Настройки звука учитывают системную громкость и беззвучный режим.
- Экспорт/импорт JSON версии 3 с проверкой версии, ссылок и дубликатов, подтверждением замены, очистка истории и полный сброс с подтверждением.
- Локальные напоминания Android с восстановлением расписания после перезагрузки и изменения часового пояса; доставка уведомления и завершение таймера проверены инструментальными тестами на эмуляторе. Точность зависит от энергосбережения Android и настроек Samsung One UI.
- Unit-тесты доменной логики (расписания, счётчик, теплокарта, неделя, форматы времени) и Android-инструментальные тесты Room, JSON-резервной копии, звуковых каналов и запуска главного экрана. GitHub Actions запускает тесты и собирает устанавливаемый debug APK.

Алгоритм тепловой карты: доля завершённых запланированных задач за день. Уровни: 0 — нет завершений/плана, 1 — менее 34%, 2 — 34–66%, 3 — 67–99%, 4 — все запланированные действия выполнены. Будущие даты остаются пустыми. Серии считаются по записанным дням с планом; даты без плана не добавляют и не прерывают серию.

## Сборка

### Через Android Studio

1. Установите Android Studio с Android SDK 35 и JDK 17.
2. Откройте каталог проекта и дождитесь синхронизации Gradle.
3. Соберите APK через **Build → Build APK(s)** либо выполните в терминале:

```bash
./gradlew --no-daemon testDebugUnitTest assembleDebug
```

APK появится в `app/build/outputs/apk/debug/app-debug.apk`.

### GitHub Actions

Workflow `.github/workflows/android.yml` на push и вручную запускает unit-тесты, собирает debug APK, затем прогоняет Android-инструментальные тесты на эмуляторе API 30 (`aosp_atd`). Последний проверенный запуск: [Actions run 40374919883](https://github.com/Partner-money/Treker/actions/runs/40374919883) — успешно. APK доступен в Actions → Artifacts (`treker-debug-apk`). Для локальной сборки нужны JDK 17 и Android SDK 35; `gradlew` скачает Gradle 8.9.

## Установка на Samsung / Android

1. Скачайте `app-debug.apk` из артефактов GitHub Actions или соберите его локально.
2. Откройте APK на телефоне. Если Android попросит разрешение, разрешите установку приложений для используемого источника (например, браузера или «Мои файлы»).
3. Подтвердите установку и запустите «Трекер привычек».
4. Разрешение на уведомления запрашивается только при включении напоминаний. Если уведомления запрещены, основные функции приложения продолжают работать.

APK CI — **debug-сборка**, подписанная автоматически отладочным ключом. Она пригодна для установки и проверки, но не предназначена для публикации в магазине. Секреты release-подписи в репозиторий не добавлены.

## Требования и структура

- Kotlin 2.0.21, AGP 8.7.3, Gradle 8.9, compile/target SDK 35, min SDK 26.
- Jetpack Compose + Material 3, Room 2.6.1, Preferences DataStore, Coroutines/Flow.
- `app/src/main/java/de/treker/habits/data` — Room, репозиторий, DataStore, формат резервной копии.
- `domain/Tracking.kt` — правила расписания, выполнения и статистики; `domain/Preferences.kt` и `domain/DayBoundary.kt` — первый день недели, форматы времени и границы дня.
- `app/schemas` — экспортируемая схема Room; каталог появляется после сборки и публикуется артефактом `room-schema`.
- `ui` — экраны, редактор привычек и ViewModel.
- `notifications` — планирование локальных уведомлений.
- `PROJECT_SPEC.md` — исходное техническое задание; `AGENTS.md` — рабочие правила проекта.

## Известные ограничения первой версии

- Напоминание на привычку — одно время в запланированные дни; используется системный неточный AlarmManager, поэтому энергосбережение Android/Samsung может задержать доставку.
- Начало нового дня сдвигает только отчётную дату (например, при старте в 04:00 отметка в 02:00 попадёт во вчерашний день); сами записи по-прежнему привязаны к календарной дате. Звук пользовательского файла хранится как ссылка с постоянным разрешением: если файл удалить или перенести, приложение вернётся к системному звуку.
- Счётчик можно изменить шагом 1 или произвольным числом; накопление времени добавляется сессиями по 15 минут или заданной длительности. Таймер сохраняет абсолютное время окончания, планирует системное уведомление и восстанавливается после повторного открытия/перезагрузки; ОС может задержать уведомление, особенно при энергосбережении.
- Аналитика строится по сохранённым дневным экземплярам. Для заполнения дня в истории откройте его в разделе «Сегодня»; задним числом расписание не создаёт пропущенные записи автоматически.
- JSON-резервная копия версии 3 включает привычки, историю, пользовательские шаблоны, звуки, вибрацию, начало нового дня и настройки поведения; импорт форматов версии 1 и 2 тоже поддержан, недостающие в старом файле настройки не сбрасываются. Импорт подтверждается до полной замены локальных данных и настроек.
- APK собирается в GitHub Actions (см. артефакт `treker-debug-apk`); в контейнере агента нет JDK и Android SDK, поэтому локальная сборка недоступна. Доставка напоминаний и звук требуют проверки на реальном устройстве.

## Проверки

Unit-тесты в `app/src/test` покрывают расписания, границы счётчика, уровни тепловой карты и серии, первый день недели, форматы времени и границы нового дня (включая переходы через месяц и год). Android-инструментальные тесты в `app/src/androidTest` проверяют идемпотентность дневных записей, счётчик, таймер после паузы/возобновления, миграции Room 1→2→3 с сохранением данных и совместимостью с текущими сущностями, доставку напоминаний (включая подавление для выполненной привычки и учёт начала нового дня), завершение таймера по alarm-бродкасту, резервную копию v1/v2/v3, звуковые каналы, запуск главного экрана, сквозной сценарий «создать привычку → отметить выполнение → увидеть в „Сегодня“ → перезапуск», прохождение счётчика до цели, старт и паузу таймера, накопление сессий через «15 мин» и диалог «Другое», статистику и журнал привычки в разделе «Прогресс», сохранение настроек темы, формата времени, первого дня недели и начала нового дня, подтверждение сброса и очистку истории (40 тестов). Все они проходят в CI на эмуляторе API 30 (`aosp_atd`); локально в контейнере JDK и Android SDK отсутствуют, поэтому проверка выполняется только через GitHub Actions.
