# Техническое задание: разработка Android-приложения для отслеживания привычек и ежедневных задач

## 1. Роль и основная задача

Ты — опытный Android-разработчик, UI/UX-дизайнер и инженер по тестированию. Твоя задача — самостоятельно спроектировать, разработать, протестировать и подготовить к установке полноценное Android-приложение для отслеживания привычек, ежедневных действий, тренировок, полезных рутин и личной продуктивности.

Приложение должно работать на смартфонах Samsung и других Android-устройствах. Основной результат — готовый устанавливаемый APK-файл, исходный код проекта и инструкция по установке.

Это не концепт, не демонстрационный макет и не набор экранов с неработающими кнопками. Все основные функции должны действительно работать, а данные должны сохраняться между запусками приложения.

Работай как автономный AI-агент: самостоятельно принимай разумные технические и дизайнерские решения, исправляй обнаруженные ошибки, запускай тесты и доводи проект до рабочего состояния. Не останавливайся после составления плана или создания интерфейса.

## 2. Технологический стек

Используй следующий стек:

- **Kotlin** — основной язык разработки.
- **Jetpack Compose** — создание современного нативного интерфейса.
- **Material 3** — базовые компоненты интерфейса.
- **Room** — локальная база данных для привычек, задач и истории выполнения.
- **DataStore** — хранение пользовательских настроек.
- **Coroutines и Flow** — асинхронная работа с данными.
- **Android Notifications и подходящие API планирования задач** — напоминания и уведомления.
- **Gradle** — сборка проекта.

Используй стабильные версии зависимостей, совместимые между собой. Не используй экспериментальные библиотеки без необходимости.

Минимальная поддерживаемая версия Android — Android 8.0 (API 26), если используемые зависимости позволяют обеспечить стабильную работу. Учитывай особенности современных версий Android и оболочки Samsung One UI.

Архитектура должна быть понятной и поддерживаемой. Можно использовать MVVM с разделением на UI, ViewModel, репозитории и слой хранения данных. Не усложняй проект ненужными абстракциями.

По умолчанию приложение должно работать полностью локально, без регистрации, обязательного подключения к интернету, серверов и платных API.

## 3. Основная концепция приложения

Приложение состоит из пяти основных разделов:

1. **Привычки** — основной рабочий экран со всеми действиями пользователя.
2. **Сегодня** — единый дневной список того, что нужно сделать сегодня.
3. **Шаблоны** — каталог готовых привычек, из которых можно быстро создавать свои.
4. **Прогресс** — статистика, календарь активности, серии и история.
5. **Настройки** — персонализация приложения, звуки, уведомления, оформление и управление данными.

Используй нижнюю панель навигации с понятными иконками. Все разделы должны быть доступны без сложных переходов по вложенным меню.

Интерфейс должен быть современным, минималистичным, аккуратным и визуально приятным. Не перегружай экраны элементами. Основные действия должны быть доступны в одно-два нажатия.

Основной язык интерфейса — русский.

## 4. Раздел «Привычки»

Это главный экран приложения, которым пользователь будет пользоваться ежедневно.

На экране должны отображаться созданные привычки в виде удобных карточек. Каждая карточка содержит:

- название привычки;
- небольшую иконку;
- категорию;
- краткое описание или цель;
- тип отслеживания;
- текущий прогресс;
- кнопку выполнения или управления действием;
- при необходимости — время следующего напоминания.

Например, пользователь может создать привычки «Отжимания», «Читать книгу», «Выпить воды», «Изучать программирование», «Утренняя зарядка» и «Медитация».

Добавь индикатор общего прогресса за текущий день: например, сколько привычек выполнено из общего количества запланированных.

Предусмотри быстрые действия с карточками: выполнить, отменить выполнение, увеличить счётчик, запустить таймер, отредактировать привычку или перенести её в архив.

В верхней части экрана размести дату, приветствие или краткую информацию о дневном прогрессе. Дизайн должен оставаться компактным и не занимать слишком много места.

Добавь кнопку создания новой привычки, заметную, но не мешающую основному содержимому.

### 4.1. Создание и редактирование привычек

При создании привычки пользователь должен иметь возможность задать:

- название;
- описание;
- категорию;
- иконку;
- цветовой акцент;
- тип отслеживания;
- цель или количество;
- расписание;
- время выполнения, если оно задано;
- напоминания;
- звук уведомления;
- дополнительные параметры, подходящие для выбранного типа.

Поддержи категории: спорт, здоровье, обучение, продуктивность, саморазвитие, отдых и пользовательские категории.

Расписание должно поддерживать ежедневное повторение, выбранные дни недели и однократные задачи. Предусмотри возможность отредактировать существующую привычку, временно приостановить её или архивировать без потери старой статистики.

## 5. Типы действий и способы выполнения

Это одна из ключевых функций приложения. У разных привычек должны быть разные способы отслеживания. Пользователь выбирает подходящий тип при создании привычки.

### Тип A. Простое выполнение

Используется для действий, у которых нет количественной цели.

Примеры: принять витамины, заправить кровать, сделать утреннюю зарядку.

Пользователь нажимает на кнопку выполнения. Привычка отмечается как выполненная. Повторное нажатие позволяет отменить выполнение.

### Тип B. Счётчик повторений или количества

Используется для отжиманий, приседаний, выпитых стаканов воды, прочитанных страниц и других измеряемых действий.

Пример: цель — 30 отжиманий.

В карточке отображается прогресс, например «12 / 30». Предусмотри кнопки «+» и «−», возможность прибавлять несколько единиц за одно действие и вручную корректировать значение.

Пользователь должен иметь возможность установить целевое количество и, если это удобно, выбрать единицу измерения: повторения, страницы, стаканы, километры или собственную единицу.

При достижении цели привычка автоматически отмечается выполненной. Если цель не достигнута, действие остаётся незавершённым, но накопленный прогресс сохраняется.

Не допускай отрицательных значений счётчика без явной необходимости.

### Тип C. Таймер или длительность

Используется для медитации, тренировок, учёбы, чтения и других действий, измеряемых временем.

Пользователь задаёт целевую продолжительность, например 20 минут, 45 минут или 1 час.

Реализуй:

- обратный отсчёт;
- запуск и паузу;
- продолжение после паузы;
- сброс таймера;
- отображение оставшегося времени;
- уведомление или звуковой сигнал по завершении;
- сохранение состояния таймера при сворачивании приложения;
- корректное восстановление таймера после повторного открытия приложения.

При выходе из приложения таймер не должен ошибочно продолжать отсчёт только за счёт счётчика секунд, который перестал обновляться. Используй надёжный механизм расчёта оставшегося времени с учётом фактического времени.

Для длительных таймеров предусмотри корректную работу в фоне, соответствующее уведомление и необходимые ограничения Android. Не запрашивай лишние разрешения.

При достижении цели засчитывай привычку выполненной, если пользователь не отменил или не сбросил сессию. Для таймера также храни фактическую продолжительность выполнения.

### Тип D. Накопление времени

Отдельно предусмотрите привычки, в которых время можно накапливать несколькими короткими сессиями за день.

Например, пользователь хочет заниматься английским языком 60 минут в день, но делает это по 15 минут несколько раз.

После завершения каждой сессии её длительность прибавляется к дневному результату. В карточке отображается накопленное и целевое время.

Не смешивай этот режим с обычным таймером обратного отсчёта. Пользователь должен понимать, выполняет ли он одну непрерывную сессию или набирает суммарное время.

### Общие правила выполнения

Все типы привычек должны работать согласованно с дневным списком и статистикой.

Предусмотри отмену случайного выполнения, корректировку количества и защиту от повторного засчитывания одной и той же завершённой сессии.

Для каждого типа действий интерфейс должен показывать только релевантные элементы управления, без лишних кнопок.

## 6. Раздел «Сегодня» — единый список задач

Это второй ключевой экран приложения.

В нём должны собираться все действия, запланированные на выбранный день, независимо от типа их выполнения.

Например:

- Отжимания — 30 повторений.
- Прочитать книгу — 20 минут.
- Выпить воды — 6 стаканов.
- Изучать программирование — 45 минут.
- Утренняя зарядка — простое выполнение.

Главное правило: привычки не должны существовать отдельно от дневного списка. Все изменения состояния привычек автоматически отражаются в разделе «Сегодня».

Если пользователь выполнил 30 отжиманий на главном экране, соответствующая задача в дневном списке тоже должна стать выполненной. Если пользователь завершил действие через дневной список, состояние карточки привычки также должно обновиться.

Используй один общий источник данных, чтобы исключить рассинхронизацию экранов.

### Отображение задач

Раздели задачи по состояниям:

- ожидают выполнения;
- выполняются или имеют частичный прогресс;
- выполнены;
- пропущены или явно отмечены как невыполненные.

При желании пользователь может отметить задачу как невыполненную или пропустить её, но эти действия должны быть различными по смыслу.

Выполненная задача должна визуально выделяться: галочка, приглушённый текст, зачёркивание названия или их комбинация.

Невыполненная задача должна иметь соответствующий значок, например крестик, только если пользователь явно указал, что она не выполнена. Не помечай все незавершённые задачи автоматически как проваленные до окончания соответствующего дня.

Добавь фильтры по состоянию и возможность просматривать предыдущие даты.

В верхней части размести дату, количество выполненных задач и прогресс за день. Предусмотри понятное пустое состояние, если на день ничего не запланировано.

## 7. Раздел «Шаблоны»

Добавь библиотеку готовых привычек, чтобы пользователь не был вынужден создавать всё с нуля.

Разделы каталога:

- утренняя рутина;
- фитнес и тренировки;
- здоровье и вода;
- чтение и обучение;
- программирование и работа;
- концентрация и продуктивность;
- отдых и восстановление.

Каждый шаблон должен иметь название, краткое описание, рекомендуемый тип отслеживания и примерную цель.

Пользователь может открыть шаблон, изменить параметры и добавить его к своим привычкам.

Предусмотри возможность создавать собственные шаблоны на основе уже существующих привычек.

Не добавляй обязательную авторизацию, интернет-загрузку или сервер для работы каталога. Базовая библиотека должна быть встроена в приложение.

## 8. Раздел «Прогресс» — визуальная история активности

Создай полноценную аналитику, вдохновлённую GitHub contribution graph и статистикой обучающих платформ вроде Stepik.

### 8.1. Тепловая карта активности

Размести календарную сетку из небольших квадратов, показывающую активность по дням.

По умолчанию отображай последний год, включая подписи месяцев и дней недели. Если удобнее для компоновки, сначала можно показать последние несколько месяцев с возможностью перейти к полному году.

Цвет квадратов должен зависеть от уровня активности за конкретный день. Например, отсутствие активности, низкая, средняя и высокая активность.

Учитывай не просто количество нажатых галочек, а содержательный дневной результат относительно запланированных действий. Продумай единый алгоритм расчёта интенсивности и документируй его.

По нажатию на квадрат открывай краткую информацию за соответствующую дату: сколько привычек было запланировано, сколько выполнено, сколько пропущено и какие действия пользователь выполнил.

Отдельно отображай легенду цветов, чтобы пользователь понимал, что означает каждый уровень.

Не окрашивай будущие дни как дни с нулевой активностью.

### 8.2. Статистика и достижения

Добавь следующие показатели:

- процент выполнения за день, неделю и месяц;
- общее количество выполненных действий;
- текущая серия успешных дней;
- самая длинная серия;
- количество активных привычек;
- наиболее регулярно выполняемые привычки;
- привычки, которые чаще всего остаются незавершёнными;
- сравнение текущей недели с предыдущей.

Реализуй понятную систему серий. День должен учитываться корректно относительно расписания пользователя: привычки, которые не планировались на этот день, не должны автоматически считаться проваленными. Не засчитывай будущие даты и не позволяй изменить исторические показатели случайными повторными нажатиями.

Добавь экран подробной статистики конкретной привычки с историей по дням и динамикой выполнения.

### 8.3. Календарь и история

Предусмотри возможность выбрать любую прошедшую дату и посмотреть состояние всех привычек за этот день.

Изменение старых записей должно быть осознанным и корректно обновлять статистику.

Не удаляй историю при переименовании, редактировании или архивировании привычки. Для исторических записей сохраняй достаточно информации, чтобы изменения названия или цели не искажали прошлые результаты.

## 9. Уведомления, напоминания и звуки

Реализуй полноценную систему напоминаний.

Для каждой привычки можно настроить отдельное расписание уведомлений. Должна быть возможность выбирать время, дни недели и включать или отключать напоминания.

Примеры:

- в 08:00 — утренняя зарядка;
- в 12:00 — выпить воды;
- в 19:00 — тренировка;
- в 21:00 — чтение книги.

В настройках приложения добавь общий переключатель уведомлений и настройки звуков.

### 9.1. Кастомные звуки

Пользователь должен иметь возможность:

- выбрать один из встроенных звуков;
- установить стандартный системный звук;
- импортировать собственный аудиофайл с устройства;
- прослушать выбранный звук перед сохранением;
- использовать отдельные звуки для разных привычек;
- отключить звук полностью.

Предусмотри короткие звуковые сигналы, звуки завершения таймера и дополнительные уведомления.

Если это технически целесообразно, добавь необязательный режим более продолжительного аудиосигнала для завершения таймера. Не делай фоновое воспроизведение музыки обязательным и не включай громкий звук без согласия пользователя.

Необходимо корректно учитывать разрешения Android на уведомления и воспроизведение звука, системную громкость, беззвучный режим и ограничения фоновой работы.

На современных версиях Android не обещай абсолютно точную доставку каждого уведомления при любых системных ограничениях. Выбери подходящие механизмы планирования, предусмотрите восстановление расписаний после перезагрузки устройства и протестируй поведение на Samsung One UI.

После отказа в разрешении уведомлений приложение должно продолжать работать, а пользователь должен видеть понятное объяснение того, как включить уведомления в настройках системы.

## 10. Раздел «Настройки»

Создай удобный экран настроек, разделённый на тематические группы.

### Оформление

- светлая тема;
- тёмная тема;
- системная тема;
- выбор акцентного цвета из нескольких приятных вариантов;
- настройки визуальной плотности, если они реализуются без перегрузки интерфейса.

### Уведомления и звуки

- глобальное включение и выключение уведомлений;
- настройки звуков;
- предварительное прослушивание звуков;
- управление разрешениями;
- общие настройки напоминаний.

### Поведение приложения

- начало нового дня и корректная работа с датами;
- первый день недели;
- формат времени;
- настройки вибрации, если поддерживаются;
- настройки отображения прогресса.

### Данные

- экспорт данных;
- импорт резервной копии;
- создание резервной копии в JSON;
- возможность очистить историю;
- возможность полностью сбросить приложение с явным подтверждением.

Экспорт и импорт должны корректно обрабатывать все основные сущности: привычки, расписания, историю выполнения и настройки, если они входят в формат резервной копии.

Импорт не должен случайно дублировать существующие данные или уничтожать их без предупреждения. Добавь обработку повреждённых файлов и несовместимых версий формата.

Пользовательские данные не должны отправляться на внешние серверы или третьим лицам. Не добавляй рекламу, обязательную регистрацию, платные блокировки или телеметрию без необходимости.

## 11. Дизайн и пользовательский опыт

Сделай интерфейс визуально качественным, соответствующим современным Android-приложениям.

Основные принципы:

- минимализм без пустого и безжизненного интерфейса;
- хорошая визуальная иерархия;
- удобное управление одной рукой;
- достаточно крупные интерактивные элементы;
- аккуратная типографика;
- единый стиль карточек, кнопок, полей и диалогов;
- плавные, ненавязчивые анимации;
- корректное отображение на разных размерах экранов;
- поддержка системного масштабирования шрифта;
- понятные состояния загрузки, ошибки и отсутствия данных.

Не используй эмодзи вместо полноценных иконок интерфейса.

Для иконок используй Google Material Symbols / Material Icons из экосистемы Google Fonts либо подходящие векторные ресурсы. Предпочтительно применять нативные векторные ресурсы Android и векторные иконки, совместимые с Jetpack Compose. Если используются SVG, обеспечь корректное преобразование или поддержку в выбранном инструменте сборки.

Не загружай иконки из интернета при запуске приложения. Основные графические ресурсы должны быть включены в проект.

Разработай отдельные состояния для пустого списка привычек, пустого дневного списка, отсутствия истории и отсутствия разрешений. Для каждого экрана продумай, что пользователь должен увидеть при первом запуске.

Не делай все экраны визуально одинаковыми, но поддерживай общую дизайн-систему.

## 12. Модель данных и корректность работы

Спроектируй локальную базу данных с сущностями для:

- привычек;
- расписаний;
- ежедневных записей;
- результатов счётчиков;
- сессий таймера;
- напоминаний;
- настроек;
- пользовательских шаблонов, если они редактируются.

Продумай связь между постоянной привычкой и её экземпляром на конкретную дату.

Для каждой даты необходимо хранить запланированное действие и фактический результат. Изменение текущей цели привычки не должно автоматически переписывать результаты предыдущих дней.

Все изменения должны сохраняться сразу и переживать закрытие приложения, перезагрузку устройства и завершение процесса приложения.

Сделай операции с данными безопасными и транзакционными там, где изменение одной сущности влияет на несколько связанных записей.

Учти переход на новый день, смену часового пояса, перевод часов и переход приложения между активным и фоновым состояниями.

Не создавай дневные задачи повторно при каждом открытии приложения. Генерируй и обновляй их идемпотентно, чтобы не возникали дубликаты.

Пользователь должен иметь возможность пользоваться приложением офлайн.

## 13. Безопасность и системные разрешения

Запрашивай только те разрешения, которые действительно нужны.

Не запрашивай доступ к контактам, геолокации, микрофону, камере или другим ненужным функциям.

Для выбора пользовательских звуков используй системный выбор файлов с минимально необходимым доступом.

Не храни пользовательские данные в небезопасном виде на внешнем сервере. Не встраивай в исходный код секретные ключи и пароли.

Приложение должно корректно работать, если пользователь откажет в необязательном разрешении.

## 14. Тестирование и критерии готовности

После реализации обязательно проверь основные сценарии.

### Сценарий 1. Создание привычки

Создать простую привычку, закрыть приложение, открыть его снова и убедиться, что привычка сохранилась.

### Сценарий 2. Счётчик

Создать привычку с целью 30 повторений, прибавить 10, затем ещё 20. Убедиться, что выполнение засчиталось, а дневной список автоматически обновился. Проверить уменьшение значения и отмену ошибочного изменения.

### Сценарий 3. Таймер

Создать таймер на короткий промежуток времени, запустить, приостановить, продолжить, свернуть приложение и дождаться завершения. Проверить фактическое время, состояние задачи и уведомление.

### Сценарий 4. Синхронизация экранов

Отметить привычку выполненной на главном экране, а затем проверить раздел «Сегодня». Повторить в обратном направлении. Не должно быть рассинхронизации или повторных записей.

### Сценарий 5. Расписание

Создать привычку на определённые дни недели. Проверить, что она появляется в нужные дни и не засчитывается как невыполненная в дни, когда её не планировали.

### Сценарий 6. Статистика

Выполнить несколько привычек в разные дни и проверить тепловую карту, дневные проценты, серии и подробную историю.

### Сценарий 7. Уведомления

Проверить выдачу разрешений, получение напоминаний, выбор пользовательского звука, отключение звука, перезагрузку устройства и поведение приложения в фоне.

### Сценарий 8. Резервная копия

Экспортировать данные, импортировать их и проверить, что история и настройки восстановились без непреднамеренного дублирования.

### Сценарий 9. Оформление

Проверить светлую и тёмную темы, разные размеры экранов, масштабирование текста и отсутствие обрезанных элементов.

Используй автоматические тесты для бизнес-логики, расчёта статистики, повторения расписаний и обработки данных, а также UI-тесты для критических сценариев, где это оправданно.

Исправь все критические ошибки компиляции и выявленные ошибки логики до подготовки итоговой сборки.

## 15. Сборка APK и итоговые файлы

Это обязательная часть задачи, а не дополнительная рекомендация.

В результате предоставь:

1. Полный исходный код Android-проекта.
2. Рабочий APK-файл, который можно скачать на Samsung и установить.
3. `README.md` с описанием проекта, требованиями, настройкой среды и инструкцией по сборке.
4. Краткую инструкцию по установке APK на Android.
5. Список реализованных функций и известных ограничений.
6. Результаты выполненных тестов.
7. GitHub Actions workflow для автоматической сборки APK, если проект размещён в GitHub или такая интеграция доступна.

В сборочных настройках предусмотрите уникальный `applicationId`, версию приложения и корректные параметры Android SDK.

Собери APK, а не только Android App Bundle (`.aab`). Если среда позволяет, подготовь подписанный release APK. Если надёжно настроить release-подпись невозможно, создай устанавливаемый debug APK и чётко объясни разницу. Не включай секреты подписи в репозиторий.

Если агент работает через GitHub, организуй проект в репозитории так, чтобы исходный код можно было скачать целиком, а APK автоматически собирался в GitHub Actions и прикладывался как доступный артефакт сборки. При наличии необходимых возможностей также подготовь отдельный release APK для загрузки.

Если в текущей среде нельзя собрать или проверить APK, не утверждай, что он готов. Вместо этого подготовь полностью собираемый проект, настрой автоматическую сборку, укажи, что именно не удалось выполнить, и предоставь точные команды для завершения сборки.

## 16. Порядок выполнения работы

## 17. Итоговое требование

Создай законченное, красивое, удобное и надёжное Android-приложение для повседневного использования.

Приоритеты по важности:

1. Корректная работа всех функций.
2. Надёжное локальное хранение данных.
3. Согласованность привычек, дневных задач и статистики.
4. Уведомления и таймер, которые работают настолько надёжно, насколько это позволяют Android и настройки устройства.

6. Удобная установка и получение обновлённой сборки APK.
